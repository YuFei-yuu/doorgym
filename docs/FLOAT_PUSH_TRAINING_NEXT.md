## 旧实验收尾与后续研究建议（历史接口）

1. **先人工检查补录视频**，重点看约 12.3 s reach、12.7 s grasp、16.3 s 解锁、16.6 s 达 80°、35.8 s 首次主成功，以及最后的通过路径。reach/grasp 是锁存阈值事件，需确认是否实际稳定抓把、有无明显碰撞或从门框侧面绕过。不能把数值主成功直接等同于可靠操作。
2. **先收尾评估基础设施，再补测试**。有界诊断原 seed 5007，补充故障前后有限性、关节/接触和动作记录，保留每次尝试并计入原账本。本次单个成功回合无故障不意味着 CUDA 问题已修复；不无依据归因显存或硬件，不修改其他任务或系统驱动。
3. 若原物理/策略配置可恢复，修订调度器只启动原计划中未启动的 90 回合，继续冻结 15000/25000、归一化、25 步推理和原判据；已启动异常不重跑替换。若需要改变物理配置，另建评估版本，不拼接原测试。原 `--resume-continuation` 在测试启动后会拒绝恢复，不能用它重新打开选模。
4. **新训练优先做小规模单因素恢复能力对照**。先核验专家能否从策略偏离状态恢复，再决定是否采集恢复轨迹；不能把未经验证的阶段脚本当作专家标签。训练与验证均保持独立、记录全部尝试。数据覆盖是待验证假设，不是已证实唯一根因。

## 继续运行的边界

每阶段三次资源采样、间隔 2 秒：最小空闲显存 ≥16 GiB、平均利用率 <70%，无合格卡退出。单 GPU/实例、nice 10、数学库/PhysX 各 2 线程；设置 `VIDEO2DOOR_GPU` 后再 source `.repro/blackwell/activate.sh`。核对锁、活动进程、模型哈希、账本与实际源码；保留旧结果，禁止重复启动或漏计。

旧实验剩余时间不是新的训练额度。新训练须另立 run_id，明确额外 GPU 预算、优化步数上限和单个主要变量。保留 `float_push_joint_v1`、25 步推理与旧主判据作可比基准；可补充独立的严格操作指标，但不要改写旧成绩。

manifest 改变时，当前严格 `train.py --resume` 不能直接恢复；应明确归一化、权重、AdamW/RNG 初始化，对照组采用相同规则。窗口/结构改变不能称完整 checkpoint 恢复。延续每 250 步离线验证、500 步不可覆盖保存、2000 步完整闭环验证及连续三点任务指标无改善早停；loss/reach/限幅改善不取消早停。

新配置可用验证种子 4100–4109、最终测试预留 6000–6029，启动前核对未被其他实验使用。旧 3000/4000/5000 系列只作历史诊断或冻结实验剩余评估，不能再称新方法的未见测试。独立测试在选模冻结后启动。
