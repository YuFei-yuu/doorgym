## 2. 与原仓库训练方法的具体差异

源码依据：

- [`dp/train_door_dp.py`](../../high-level/dp/train_door_dp.py)：`parse_args`、`compute_stats`、`main`。
- [`dp/door_dp_common.py`](../../high-level/dp/door_dp_common.py)：`DoorDPPolicyController`。
- [`dp/models/door_diffusion_policy.py`](../../high-level/dp/models/door_diffusion_policy.py)：`DoorDiffusionPolicy`、`encode_obs`。
- [`dp/docs/door_dp_usage.md`](../../high-level/dp/docs/door_dp_usage.md)：完整训练示例。
- [`learning/train.py`](../../high-level/float_ik/learning/train.py)、[`learning/policy.py`](../../high-level/float_ik/learning/policy.py)：本轮实际实现。

| 项目 | 原仓库默认/示例 | 首轮浮动底座实现 |
| --- | --- | --- |
| 模型与目标 | 四路图像编码、条件残差 1D 网络；扩散噪声 MSE | 复用同一网络类与 MSE，输入维度按新 schema 调整 |
| 优化步数 / batch | 100000 / 64 | 5000 / 16 |
| 观测 / 预测 / 执行窗口 | 16 / 32 / 16 | 4 / 16 / 4 |
| 扩散训练步 / 默认推理步 | 100 / 100 | 100 / 25 |
| 学习率 / 梯度裁剪 | 1e-4 / 1.0 | 相同 |
| AdamW weight_decay | 显式 1e-6 | 未显式传入，PyTorch 默认 0.01 |
| 标准差下限 | 1e-6 | 0.01；只由成功训练回合计算统计量 |
| DDPM clip_sample | True | False |
| 数据 | LeRobot；原包装器接低层行走控制器 | 直接读取同步 NPZ；浮动底座独立执行器 |
| 10D 动作 | 底座 vx/yaw、末端 xyz/xyzw、夹爪 | 底座 vx/vy/yaw-rate、6 关节和夹爪位置目标 |
| 保存与评估 | 覆盖 model_latest；该训练入口无独立验证循环及完整 RNG 恢复 | 不可覆盖分步 checkpoint、固定验证、完整 RNG/优化器恢复、独立 Gym 评估 |

两套 10D 动作语义不同，不能交换 checkpoint。原文档的 100000 步是训练示例，不是该浮动底座任务已成功的实验证据。

仅按 batch 与步数计，原默认训练读取约 640 万个窗口，本轮约 8 万个窗口，相差 80 倍；优化更新次数相差 20 倍。这不代表 80 倍独立信息，也不代表训练时间必然相差 80 倍：窗口高度重叠，原数据量、场景和采样路径也不同。

原 `clip_sample=True` 默认裁剪的是归一化后的 x0 到 [-1,1]。对于 z-score 动作，这相当于均值附近约 ±1 个标准差，**不是覆盖完整专家动作范围的物理限幅**。不能不检查训练动作分布就恢复该选项。当前 False 可放大异常采样输出，但仅凭限幅比例无法确定它是失败根因。原/新标准差下限和 weight_decay 的差异也应显式记录、逐项实验，而不是一次全部更改。

4 帧在本轮 60 Hz 下只有 50 ms 的首末帧跨度；16 帧也仅为 250 ms。网络没有持续的循环隐状态，长时间保持后何时换动作可能有歧义。更长历史可能有帮助，但不能保证解决多秒阶段记忆。增大观测窗口还会改变条件层参数尺寸，当前 checkpoint 不能按完整模型原样恢复；需要新训练或明确记录部分权重初始化。

## 3. 延长训练能否完成：初步结论

**值得做一次受控续训，但不能认定按原配置多跑几小时就能学会，也不能据 5000 步失败认定这条路线无效。**

支持续训的证据：优化量远小于原默认；验证 loss 与录制观测上的动作误差仍改善；真正的优化循环只运行约一分钟。更精确的动作预测可能降低首次偏离。

反对直接长跑的证据：多个 checkpoint 闭环均失败，5000 步甚至在前 0.7 秒内出现大量限幅；14 条单门训练轨迹覆盖有限。训练观测上的低误差不约束偏离后状态的行为，重复更多相同数据也不会自动增加恢复状态覆盖。这些数据支持优先检查早期闭环失稳，但尚未证明具体是采样、归一化、动作反馈、历史不足或数据覆盖中的哪一项。

建议的次序：

1. 检查首次 1 秒：obs/action 帧对齐、各状态通道 z-score、首个动作误差、上一执行动作、关节速度、底座坐标变换与限幅时间。只用已有测试集做历史失败解释；新的配置选择使用新验证种子。
2. 同一 checkpoint、固定新验证场景，对照 25 与 100 推理去噪步，先少量回合；记录真实时延。更长采样不等于必然更好。
3. 保持数据、结构和采样配置不变，从 5000 步做有界续训，最多新增 20000 步，按固定验证点判断“是否只是优化不足”。不要同时换窗口、归一化、数据和采样器，导致无法归因。
4. 只有实际闭环改善后再扩大数据或另做一个配置消融。若连续三个完整评估点成功率和最终门角均不改善，保存并停止；reach、首次限幅时间和离线误差作为诊断保留，不用它们冒充主任务改善。
5. 若同配置续训仍失败，再决定动作约束、历史/记忆或恢复状态数据的实验。不要自动转 PPO/DAgger，更不要在评估时引入专家阶段控制。

还需处理两项工程边界：当前 `train.py --resume` 要求 manifest 完全相同，不能直接对加入新数据的 manifest 续训；扩充数据必须明确是固定旧归一化的兼容恢复，还是新统计量/新模型训练，不能混用旧输入输出尺度。旧 `bounded.py` 总上限写死 7200 秒，旧 driver 的种子和阶段预算也是首轮配置，不能直接拿它当额外 6 小时启动器。
