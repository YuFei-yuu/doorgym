# R9完整任务专家扩采外围工具

本目录只负责冻结参数、独立场景编排、证据核验、候选来源和数据诊断。
`fullcycle_expert.py`、场景映射、物理、轨迹和实时记录器继续使用R8执行源码。
本轮预算是最多64个新场景、每场景180秒，累计候选达到50即停；不能用这些入口补跑。

- `collect.py prepare`：冻结62100–62163的64份参数、R7物理和相机姿态；逐字节保留R8六条候选。只在不存在的新run执行一次。
- `collect.py preflight/attempt`：一份单场景清单调用原R8执行入口；外层独占claim防重试，统一预算防越界。
- `parallel.py`：首回合记录检查后采用的正式批次入口；每组最多8个独立单环境进程，先锁定并三次核对空闲GPU1/2。原参数、dt、专家及相机不变。组内系统性错误会中断本组其他进程并保留已启动场景。
- `validate.py`：继承R8记录/原深度哈希/视频检查；随机回合不做名义R7轨迹逐位相等断言。
- `review.py`：继承R8对齐接触、独立保持计时和原片抽帧；额外报告负向原始命令，不改写数据。
- `audit.py`：分开记录自动终态和入选；负向命令隔离，原片审查后才复制合格候选。审查元数据不作策略输入。
- `check_dataset.py`：实际训练factory/DataLoader、完整状态动作数值及chunk100/padding检查，仅创建配置，无模型。
- `check_alias.py`：原图/Joint9的有限近邻诊断，分别核对当前、前25步及100步监督；不作为本轮采集阻断条件。
- `aggregate.py`：来源哈希、初态覆盖、尝试/待审/失败清单和资源汇总。

`launch.sh`/`batch.sh`为首回合启动记录。`batch.sh`的裸Gym后处理解释器缺PyAV，首回合物理执行及记录验证已完成后，原证据改用既有ACT环境审查；没有重开场景。后续使用`parallel.py`的ACT后处理路径，保留初次错误日志。不要把bootstrap脚本作为新一轮默认入口。

参数和执行源码冻结清单在run内；本目录后加的只读诊断和调度文件以各组绑定、实际提交及最终diff为准，不重写执行时清单。历史数据/模型/环境不清理；所有数值检查在pro5000执行。原始执行录像与状态回放严格区分，本轮未使用回放造证据。

本轮真实factory窗口读取触发长视频float32时间戳比较错误，流水线在`dataset-check`中止。`reader_failure.py`仅复现同一异常并记录默认dtype和原生PTS，不改变守卫或数据。后续特征检查独立阶段、扩展歧义诊断、正式DataLoader批次和汇总绘图未运行；脚本存在不代表验收通过。详见相邻`FULL_TASK_EXPANSION_R9_RESULT.md`。
